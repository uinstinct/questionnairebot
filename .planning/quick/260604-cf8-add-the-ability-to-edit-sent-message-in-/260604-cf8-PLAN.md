<objective>
Let the user edit a previously-sent Telegram answer and have that edit rewritten back into the
matching answer on disk. Telegram delivers an edited message as `update.EditedMessage` (keeping
the original `MessageID`); the bot matches that id against a `message_id` now stored on every
recorded answer and rewrites the answer text in place — in `answers.yaml` for completed entries
and in `session.yaml` for an in-progress session.

Purpose: implements the LOCKED CONTEXT.md decisions for quick task 260604-cf8 — any past answer
is editable, matched by message id, with a precise legacy-data fallback that never clobbers an
unrelated answer. This intentionally reverses PROJECT.md's "no editing past answers" non-goal for
edits only (user-approved).

Output:
- `AnswerPair.MessageID` persisted everywhere (omitempty; legacy files stay valid).
- `storage.UpdateAnswerByMessageID` / `storage.UpdateLastAnswer` (in-place atomic rewrite).
- `session.Manager.UpdateAnswerByMessageID` / `UpdateLastAnswer` (under the mutex).
- `QuestionFlow.HandleEditedAnswer` + dispatcher routing of `update.EditedMessage`.
</objective>
